# Salon Site Auditor

サロンデモの品質を自律評価し、優先度付きの改善レポートを出力します。
受注前のデモ品質確認・クライアントへの改善提案書作成に使います。

## 使い方
```
/salon-audit [--fix]
```

`--fix` フラグを渡すと、P0/P1 の問題を自動修正します。

## 評価項目と実行手順

### STEP 1: ファイル読み込み

以下を全て読み込む:
- `index.html`, `book.html`, `reservations.html`
- `css/style.css`
- `js/utils.js`, `js/app.js`, `js/book-page.js`, `js/reservations-page.js`
- `js/data/settings.js`, `js/data/stylists.js`, `js/data/menus.js`
- `js/metrics/*.js`

### STEP 2: 評価チェックリスト

以下の各項目を評価し、P0/P1/P2/P3 の優先度を付ける。

#### A. データ品質（ハードコード検出）
Grep で以下のパターンを検索:
- `'20[0-9]{2}-[0-9]{2}-[0-9]{2}'` → ハードコード日付
- `'2026'` → 年号ハードコード
- 特定のスタッフ名が文字列リテラルに出現していないか

優先度:
- P0: 将来に確実に壊れる（例: 今年の日付が固定）
- P1: データ更新時に壊れる

#### B. UX 完全性
- [ ] 全モーダルに Escape キー対応があるか
- [ ] 全フォームに送信後のフィードバック（トースト/メッセージ）があるか
- [ ] エラーメッセージが表示されるか（境界値テスト）
- [ ] 空状態（データ0件）のUI が定義されているか
- [ ] ローディング中の表示があるか（外部データを使う場合）

#### C. アクセシビリティ
- [ ] 全 `<input>` に `<label for="">` または `aria-label` があるか
- [ ] エラー表示要素に `role="alert"` があるか
- [ ] モーダルに `aria-modal="true"` と `aria-labelledby` があるか
- [ ] インタラクティブ要素が `Tab` キーで到達可能か
- [ ] color-only な情報表現（色だけで意味を伝えていない）か

#### D. モバイルレスポンシブ
- [ ] `meta viewport` が設定されているか
- [ ] 横スクロールが発生しないか（特に表・グリッド）
- [ ] タッチターゲットが 44px 以上か
- [ ] 768px 以下でレイアウトが崩れていないか
- [ ] テーブルが `overflow-x: auto` のラッパーに入っているか

#### E. セキュリティ・デモ安全性
- [ ] `noindex, nofollow` が全ページに設定されているか
- [ ] `innerHTML` への直接ユーザー入力代入がないか（XSS）
- [ ] 外部リソース（CDN）は SRI ハッシュ付きか

#### F. コード品質
- [ ] `console.log` が本番コードに残っていないか
- [ ] 同一ロジックが3ファイル以上で重複していないか
- [ ] コメント化されたコードが残っていないか

#### G. デモとしての完成度
- [ ] サンプルデータが最低6ヶ月分あるか
- [ ] 全KPIカードに意味のある数値が表示されているか（全て「—」でない）
- [ ] 新規/再来両方のデータが含まれているか
- [ ] キャンセル・無断キャンセルのデータが含まれているか

### STEP 4: --fix フラグの場合

`$ARGUMENTS` に `--fix` が含まれる場合:
1. P0 / P1 の問題をすべて自動修正する
2. 修正ごとにコミットする
3. 完了後に再度 STEP 2 を実行してゼロ件を確認する
4. 「全P0/P1 修正完了」と報告する
