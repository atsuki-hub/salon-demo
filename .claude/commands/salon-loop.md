# Salon Autonomous Improvement Loop

サイトを自律的に評価→改善→コミットを繰り返すループを実行します。
各イテレーションで発見した問題を修正し、変更をコミットします。

## 使い方
```
/salon-loop [iterations=4]
```

デフォルトは4イテレーション。数値を渡すと回数を変更できます。

## 改善優先順位フレームワーク

各イテレーションは以下の優先順位で問題を選ぶ:

### P0（必ず実施）
- ハードコードされた日付・データ値
- JS エラーを引き起こすバグ
- 表示が壊れるレイアウト崩れ

### P1（できるだけ実施）
- UX の欠落（フィードバックなし、フォームの入力補助なし）
- アクセシビリティの問題（ARIA、フォーカス）
- モバイルレスポンシブの問題

### P2（余裕があれば実施）
- 機能追加（CSV出力、検索、フィルター）
- デザインの改善（ホバー効果、アニメーション）
- パフォーマンス改善

### P3（最後のイテレーションで実施）
- コードの整理・重複除去
- ドキュメント追加

## 実行手順

### 各イテレーションの流れ

1. **評価フェーズ** (5分)
   - 全ファイルを読み込む
   - 上記チェックリストを実行
   - 今回のイテレーションで修正する問題を1〜3個選ぶ
   - 「イテレーション X: 【何を修正するか】」を宣言する

2. **実装フェーズ** (実装)
   - 選んだ問題を修正する
   - 関連するCSS/JS/HTMLを必要に応じてすべて更新
   - 副作用がないか確認する（既存機能が壊れていないか）

3. **コミットフェーズ**
   - `git add` して `git commit` する
   - コミットメッセージは `fix:` / `feat:` / `style:` プレフィックスを使う

4. **次のイテレーションへ**
   - 完了したら次のイテレーションに進む
   - 前のイテレーションで発見した副次的な問題は次のイテレーションで対処

### 終了条件
- 指定イテレーション数に達した
- P0/P1 の問題がゼロになった

## 完了後の報告フォーマット

```
## 改善ループ完了レポート

実施イテレーション: X回
コミット数: X件

### 実施した改善

| イテ | カテゴリ | 改善内容 |
|------|---------|---------|
| 1 | バグ修正 | ... |
| 2 | UX改善 | ... |
...

### 残課題（次回以降）

| 優先度 | 問題 |
|--------|------|
| P2 | ... |
...

### git log
【直近のコミット一覧】
```

## 注意事項
- 1イテレーションで変更するファイルは最大5ファイルに絞る（スコープ管理）
- 大規模リファクタリングは行わない（既存機能を壊すリスク）
- 各イテレーション後に git status を確認してクリーンな状態を保つ
- 同じ問題を2回修正しない（イテレーション間で変更履歴を把握する）
